**Known — the prevention mechanism is in the acceptance path.** In `news/trajectory.py:651–675`, the proposal is retained and structurally validated before a separate `coherence` invocation. Its decision is also retained and validated. Only then are sources materialized and the journal transaction entered (`677–690`). Missing, invalid, incomplete, duplicate, unsupported or uncertain review verdicts fail closed. `validate_coherence` checks that verdict indices cover every proposed story exactly once; acceptance requires all of them to be `supported`. There is no branch that converts reviewer failure into acceptance or silently falls back to the old one-call path.

This prevents acceptance only to the extent that the model reviewer correctly judges the evidence. The reviewer uses the same `gpt-6-astra` / `medium` application model in a new invocation, with a different task prompt. It is separate execution, not demonstrated statistical independence from the author. Passing its schema or obtaining `supported` is not by itself semantic correctness.

**Known — reused stories expose the full stored matter.** `coherence_payload` (`trajectory.py:722–742`) builds prior context from a fresh `project(db, as_of=...)`, then includes all projected events and every projected original source belonging to each reused story. It does not reuse the bounded author-retrieval `history`. This is the important protection against the observed cat/ship problem: renaming the contaminated story does not hide its ship event from the reviewer when the author has seen only its cat-related retrieved event. The current proposed decision, all current sources and the complete reused story are supplied together.

The prompt explicitly distinguishes a continuing named matter from a single occurrence. It allows separate developments within one matter, rejects reuse of an event for another occurrence, and rejects inherited unrelated events. It does not require a singleton thin article or cautious digest to prove a nonexistent multi-article link. This avoids turning every RSS limitation into automatic rejection while still reviewing actual grouping.

**Known — accepted-memory protection and remaining recovery limit.** The existing identity restrictions remain: accepted captures cannot silently move and reused event IDs must retain their parent story. The coherence task is prohibited from rewriting or repairing decisions. Its rejection leaves the batch unaccepted with both artifacts available. This is automatic detection/containment, not automatic repair of an already contaminated journal. Stories not proposed or reused by the current batch are not audited retroactively. Old generated pages remain old evidence.

Do not describe this candidate as having repaired the existing dogfood history. A later inherited-contamination test should demonstrate automatic rejection and an unchanged accepted journal. A fresh replay from original sources can demonstrate improved automatic reconstruction, but it does not replace showing that the exact original bad proposal would be rejected. Manual story/event movement or hand-curated replacement assignments would violate the updated `AGENTS.md`.

**Known — bounded execution and artifacts.** Proposal and review use the same run directory and retained task-specific subdirectories. Both coherence files participate in the run fingerprint, so changing the gate cannot reuse the old one-call fingerprint. The timer starts immediately before the author call; only `timeout - elapsed` is passed to the review. If that remainder is exhausted, review is not launched and no run is accepted. A second elapsed-time check after the review also rejects a late `supported` answer, retaining it as evidence. Review payload size is checked before its call. Existing transaction behavior also rolls acceptance back on output/render/commit failure.

The time contract is a shared model-call budget, not a hard end-to-end wall-clock limit: capture/retrieval precede the timer, `run_task` performs setup before `communicate(timeout=...)`, and termination/validation/output have overhead. Do not claim a strict all-inclusive batch duration bound unless an outer deadline enforces it. No new independent full reviewer timeout is being granted, which is the essential resource-control property here.

**Known — long stories can stop processing.** A complete reused story may exceed `max_context_chars` even when the bounded author payload fits. The candidate correctly rejects rather than truncating its safety context. But one sufficiently long story can exceed the cap even in a one-article batch; “use a smaller batch” is then not a recovery solution. The daily FIFO stops on the first failed batch, so repeated daily attempts could repeatedly spend an author call before encountering the same review-size barrier. This is an explicit supported-capacity limit, not a demonstrated current workload failure or a reason to drop history silently.

`tests/test_coherence.py` now tests a middle historical event omitted by author retrieval but present with all original text in the reviewer, and a full-history size failure with no second call or journal insertion. Suggested diagnostic improvement, not a pre-live blocker: report review size/limit directly as well as the failure stage; the present error plus preserved `review-input.json` is inspectable but less direct than the author retrieval diagnostics. A scalable review scheme should be a later evidence-led change if real histories hit this barrier, not an untested truncation added now.

**Known — title evidence retains field provenance.** The trajectory schema accepts an explicit `field` in `{title,text}` and the exact old body-reference form. Missing `field` means `text`; an unsupported field cannot pass schema validation. `_references` selects the designated saved field, preventing a title-only fact from being cited as body text. `_materialize` writes the explicit field for new results; the renderer labels new headline/body evidence while leaving old fieldless references readable. `project` and rendering normalize reference identity using the same legacy default.

The checks also avoid inventing a comparison simply by citing identical words once as a title and once as a body. Exact-source and article-coverage guards are unchanged. The prompt requires attribution and warns that a headline is neither independent corroboration nor proof of occurrence time, and must not silently override a conflicting or corrective body. These are appropriate constraints; actual title/body conflict handling remains a model-evidence question.

Inspected tests cover current and historical headline evidence, correction and comparison fields, incorrect field/quote rejection without acceptance, self-comparison, field-aware rendering, and unchanged legacy journal text. These tests use a supported-review stub; they exercise source/field mechanics, not the truth of the new semantic gate. The completed coherence tests separately cover unsupported/uncertain answers, malformed/incomplete coverage, invalid proposals before review, review timeout, remaining shared time, late supported answers, immutable prior acceptance/output artifacts and complete history beyond retrieval. This reviewer read these tests but did not rerun the suite.

**Known — two-call accounting preserves uncertainty.** `news/daily.py:153–267` records separate proposal/reviewer diagnostics and counts confirmed launches, unknown launch status and confirmed launches with unknown usage independently. Known usage from either call survives missing or malformed metadata from the other; reuse incurs no new charge. Report totals aggregate those per-call counts (`477–486`) rather than treating a batch as one invocation. Inspected tests cover first/second-call failures, incomplete diagnostics, rejection, timeout and reused acceptance. No accounting blocker was found. README, DOGFOOD and the daily routine now describe two calls, a shared deadline, long-story capacity and the absence of retroactive repair.

**Known — parser fix is general and small.** `feeds.py` now selects supported expanded XML names instead of arbitrary matching local names. RSS 2 description, RSS 1 description/Dublin Core date, the RSS content module and Atom content/summary are explicitly recognized. `media:content` cannot shadow article text. Empty or HTML-only-whitespace preferred content falls through to the next supported text field. The implementation uses the existing HTML/text handling and standard library; no site-specific identifiers or news-case exceptions are present.

The supplied tests cover the frozen Guardian collision, real `content:encoded`, empty preferred fields, Atom XHTML/text/HTML, unsupported lookalike namespaces, metadata lookalikes, media-only invalidity and RSS 1 fields. This deliberately narrows accidentally accepted arbitrary namespaces to supported feed vocabularies. It does not make the parser a full general-purpose feed library, which is appropriate for the present scope.

**Known — source/proposal injection boundaries are preserved.** Both tasks label source fields and the proposal as untrusted data. The new reviewer uses the same existing `run_task` process isolation: ephemeral execution, temporary working root, ignored project/user instructions, configured tools/plugins/MCP disabled, and bounded structured output. Nothing evaluates quotes or titles as code or imports instructions from the source pack. These controls reduce tool-mediated risk; natural-language prompt injection remains a semantic robustness question and should not be advertised as impossible.

**Simplicity judgment.** One proposal plus one explicit yes/no/uncertain gate is understandable and appropriate to the unattended prevention requirement. Returning per-story verdicts gives a useful failure trail without introducing a repair planner or a service. The full-history cost and whole-batch rejection are deliberate tradeoffs. Do not add a manual approval queue, case-specific exceptions, or a title blacklist as a substitute for source-supported grouping. Do not add a third model call or automatic retries without a new explicit budget and protocol.

**Required live protocol distinctions before launch.**

- Detection: pass the exact preserved ship/cat bad decision and its original sources to the reviewer. Include an inherited-contamination proposal against the full unchanged contaminated prior story. This tests the failure that actually happened.
- Prevention: separately generate a new proposal from the original pre-failure sources/context and run the production gate. A clean author response alone does not show that the gate could detect the original failure; a rejected injected old proposal alone does not demonstrate successful automatic processing of the batch.
- Controls: retain valid grouping of the two ship reports and the cat follow-up, and distinct events that properly share a named story. Measure false rejection as well as false acceptance. Rejected batches are unavailable reader outputs, not successful complete processing.
- Fresh cases: keep the three independently source-labeled cases and their frozen expectations hidden from the evaluated models. Preserve exact title/body fields and the supplied competitor. Label fixed/adapted context honestly; do not call this an end-to-end test of production retrieval or of a months-long journal.
- Ceiling: count every author and coherence CLI launch, including rejected proposals, timeout attempts, diagnostics-only calls and repeated controls, toward the total of 24. Unknown usage must remain unknown. Frozen historical answers are not fresh stochastic controls. Freeze code/task/schema/source hashes and exact request order before model work, and retain unsuccessful artifacts.
